# Fork changelog

Changes in this fork (mchowning/pi-claude-bridge) that are not upstream. Upstream's `CHANGELOG.md` is kept identical to theirs so merges never conflict on it.

## UNRELEASED

- **Fix: a restarted pi resumes its Claude Code session instead of rebuilding it** — the link from a pi session to its CC session lived only in memory, so after `pi --continue`/`--session`/`/resume` the first turn rebuilt the whole history into a new CC session (a full prompt-cache rewrite), and a review-thread fork started before that turn found no session to fork from. After each good run the bridge now appends a `claude-bridge-session` entry to pi's session file (`{ piSessionId, ccSessionId, cursor, cwd }`), and on `session_start` (`startup`/`resume`) adopts the latest one only when it is on the loaded branch, belongs to this pi session and cwd, its CC file exists, its cursor fits pi's history, and nothing after it in the file (on any branch) touches the model's context. A `context_edit` since the last pointer or rebuild marks the session for rebuild instead of being certified. `src/session-pointer.ts`; covered by `tests/unit-session-pointer.mjs` and `tests/unit-session-pointer-wiring.mjs`, and by the cache-flow matrix (`tests/cache-flows.mjs`).
- **Fix: never resume a Claude Code session from another cwd** — a CC session lives under the project dir of the cwd it was written in, but REUSE, the shorter-context preserve path and fork-from adoption did not compare the session's cwd with the turn's. A mismatch now rebuilds under the current cwd. Covered by `tests/unit-sync-cwd.mjs`.
- **Fix: `/reload` no longer drops the Claude Code session** — `session_shutdown` cleared the shared session on every reason, so after `/reload` the fresh module instance rebuilt the whole history into a new CC session on the next turn (a full prompt-cache rewrite; ~300k tokens on a long session), and a process forking from this one (`CLAUDE_BRIDGE_FORK_FROM`) found no published session to copy. The reloading instance now hands its session to the next one through a `globalThis` slot keyed by pi's session file, adopted only on `session_start` with reason `reload`, so in-process isolated subagents never pick up the parent's session. Covered by `tests/unit-reload-handoff.mjs`.
